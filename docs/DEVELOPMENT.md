# Development

## Toolchain

Use Bun 1.3.14 and Node.js 24. Install dependencies from the repository root with `bun install --frozen-lockfile`. The install hook generates TypeScript environment types from `apps/web/.env.schema`; it does not need production credentials.

Follow the [README](../README.md#run-locally) to create your own Convex development project, configure authentication, and start the app.

## Environment reference

### Web app: `apps/web/.env.local`

Copy `apps/web/.env.example`, then replace both URLs with the values for your own deployment:

| Variable               | Purpose                                                   |
| ---------------------- | --------------------------------------------------------- |
| `VITE_CONVEX_URL`      | Convex query/mutation endpoint, ending in `.convex.cloud` |
| `VITE_CONVEX_SITE_URL` | Convex HTTP/auth endpoint, ending in `.convex.site`       |

These are public build inputs. Never put a secret in a `VITE_*` variable. `.env.production.local` is generated by the production build helper and ignored by Git.

### Convex server environment

Run `bunx convex env set NAME VALUE` from `packages/backend`, or use your deployment's Convex dashboard. These values belong on the Convex deployment, not in the browser environment file.

| Variable             | Local/self-hosted value                                              |
| -------------------- | -------------------------------------------------------------------- |
| `SITE_URL`           | `http://localhost:3001` locally; your HTTPS web origin in production |
| `BETTER_AUTH_SECRET` | Generate a unique secret with `openssl rand -hex 32`                 |
| `CAPY_SELF_HOSTED`   | `true` to keep editing enabled without hosted subscriptions          |

The CLI writes the selected deployment to ignored `packages/backend/.env.local`. Do not copy another contributor's file or use Capy's hosted backend. Always verify the deployment shown by the CLI before pushing functions.

Hosted billing additionally uses `STRIPE_WEBHOOK_SECRET`, `STRIPE_LIVE_MODE`, and `STRIPE_PORTAL_URL` on Convex, and `STRIPE_SECRET_KEY` on the Cloudflare Worker. They are not needed for self-hosted mode.

## Commands

| Command              | Result                                                                           |
| -------------------- | -------------------------------------------------------------------------------- |
| `bun run dev`        | Web app and Convex development watchers                                          |
| `bun run dev:web`    | Web app only, on port 3001                                                       |
| `bun run dev:server` | Convex development watcher only                                                  |
| `bun run dev:setup`  | Select/configure a Convex project and wait for the first successful push         |
| `bun run check`      | Formatting, lint, production build, and workspace TypeScript checks              |
| `bun run test`       | Automated tests                                                                  |
| `bun run format`     | Apply formatting                                                                 |
| `bun run build`      | Build the web app without deployment                                             |
| `bun run deploy`     | Deploy the selected project's production Convex functions and Cloudflare web app |

## Dependency overrides

The root manifest pins patched Hono and UUID resolutions to avoid older transitive/peer versions. Better Auth stays within the Convex adapter's supported 1.6 range. When changing these pins, check the consumer API and run import/export tests and `bun audit`; do not remove an override just to simplify the manifest.

The Bun patch in `patches/` fixes the Convex adapter's React client types for Better Auth 1.6.22 and later ([upstream issue #420](https://github.com/get-convex/better-auth/issues/420)). It uses the concrete Convex/cross-domain plugin types rather than a generic plugin union that makes session data infer as `never`. The patch changes types only, not authentication behavior. Remove it when the adapter ships a compatible fix; rerun the build and verify sign-in/session refresh when updating either authentication package.

## Dependency maintenance

Dependabot checks routine updates monthly and groups them into one app-dependency PR and one GitHub Actions PR, with at most one open version-update PR per ecosystem. Major version upgrades are reviewed manually. Security updates have separate groups and are not delayed by the monthly version-update schedule or its PR limit; the minor/patch allow rule does not exclude security fixes. See [GitHub's configuration reference](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference).

The root `vite` override resolves to Vite+'s `@voidzero-dev/vite-plus-core`. A standalone Vite manifest bump does not change the installed runtime. Upgrade Vite+ and its matching override together when adopting a new toolchain release.

## Tests

Tests live in `apps/web/src/server`. They cover synthetic Pulley workbook parsing and export round trips, decimal totals, SAFE modeling, vesting boundaries, URL redirects, hosted/self-hosted billing policy, and Stripe signature verification. Tests run without live Stripe, Cloudflare, or Convex credentials.

They do not replace end-to-end authorization or import checks against a disposable Convex deployment. For access-control changes, test at least two unrelated users and a restricted stakeholder invitation. For importer changes, follow the [manual acceptance steps](PULLEY_IMPORT.md#verify-a-migration).

## Common setup problems

- **Missing `VITE_CONVEX_URL`:** fill in `apps/web/.env.local` and restart the web dev server.
- **Auth errors or rejected origin:** `SITE_URL` on Convex must exactly match the web origin, including the local port. Check that the `.cloud` and `.site` URLs belong to the same deployment.
- **First backend push waiting:** set the server environment variables in another terminal after the project is configured; `dev:setup` retries until it succeeds.
- **Unexpected billing prompt on your own deployment:** set `CAPY_SELF_HOSTED=true` on that Convex deployment. This setting never removes company membership checks.
- **Schema/types appear stale:** run the Convex watcher, then `bun run check`; route and environment types also regenerate during installation/build.
- **Formatting noise in generated assets:** screenshots and private capture output belong in `artifacts/` or `.private/`, both ignored. Curated documentation images live in `docs/images/`.

Read [CONTRIBUTING.md](../CONTRIBUTING.md), run both checks, and include the behavior change and verification in the PR description. Keep production deploy keys and private data out of local fixtures and CI.
