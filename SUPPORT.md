# Getting help

| Need                                                   | Where to go                                                                             |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| Reproducible bug                                       | [Bug report](https://github.com/zain/capy/issues/new?template=bug_report.yml)           |
| Feature proposal                                       | [Feature request](https://github.com/zain/capy/issues/new?template=feature_request.yml) |
| Setup or usage question                                | [GitHub Discussions](https://github.com/zain/capy/discussions)                          |
| Private migration, account, or hosted billing question | [hello@capyinc.com](mailto:hello@capyinc.com)                                           |
| Vulnerability                                          | [Private security report](https://github.com/zain/capy/security/advisories/new)         |

For technical reports, include the release/commit, operating system, Bun and Node versions, whether you are using the hosted service or your own deployment, reproduction steps, and redacted errors. Use synthetic records and `example.com` addresses.

Do not attach a real cap table, signed agreement, session cookie, environment file, or private invitation to a public issue. For a migration involving private records, email the team first to arrange how to share them.

Community support is best effort. No support-response guarantee is attached to the open-source license.
